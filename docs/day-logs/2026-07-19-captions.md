## Completed

The Day 6 goal — **turn a rendered carousel into a postable thing** — a caption per generation, written from the actual content, editable.

- **`caption` edge function** — one entry point. `POST {generation_id}` → Claude **Sonnet** (`claude-sonnet-5`) writes a caption from the generation's *content* (trip name + theme display name + the selected photos' `content_category` mix via a pure `summarizeCategories` helper + slide count), persists `caption` + `caption_mode='generated'`, returns it. `POST {generation_id, custom_text}` → persists the user's own text verbatim as `caption_mode='custom'` with **no model call**. Deployed live (v1, `verify_jwt`).
- **Ownership** — the generation is read through the caller's **RLS-scoped** client (`generations_owner_all` policy), so a non-owner (or nonexistent id) → `403` with no existence leak; all service-role reads/writes happen only *after* that gate, keyed off ids derived from the already-owned generation.
- **Reveal caption UI** — the carousel screen loads the stored caption, **auto-generates on first reveal** if empty, and shows it in an editable multiline field with **Regenerate** (write a new one) and **Save** (persist edited text as custom). Caption failures now surface inline without blanking the loaded carousel.
- **No schema change** — `generations.caption` + the `caption_mode` enum already existed.
- **`/simplify`** — focused self-review (not the 4-agent fleet) given a small, clean, pattern-following diff already quality-reviewed by the opus whole-branch pass: caption files correctly reuse `stripMarkdownFence`/`getServiceClient`/`serveJson`, `summarizeCategories` is genuinely new, no duplication or dead code.
- **`/security-review`** — no HIGH/MEDIUM findings (see below).

Both tasks passed a task-scoped spec+quality review; the final whole-branch review (opus) returned **ready-to-merge, no Critical/Important**, with the mobile→function→schema contract and the authorization model verified.

## Assumptions / gaps (accepted or deferred, not fixed)

- **Text-based captions, not vision** — the caption is built from the category mix + trip + theme, one cheap Sonnet text call. Sending the hero photo to Sonnet for an image-aware caption is a noted later refinement.
- **Live deployed caption needs the `ANTHROPIC_API_KEY` edge secret** — the deployed `caption` function can't call Anthropic until the user sets it (a credential action reserved for the user); `/run` verified locally against `.env`. (Carried over from Days 4–5: `rank-media`/`generate` also still need redeploy + secrets before production.)
- **No rate limit on Regenerate** — a user can repeatedly tap Regenerate, each a Sonnet call (cost). It's the organizer's own generation; a real quota belongs with the free-tier limits work (master-plan Days 10-12). Sub-threshold in the security review (cost/DoS-class, out of scope).
- **Minor Reveal UX, from the brief, MVP-acceptable** — the caption handlers don't guard against post-unmount `setState` (harmless under React 18); tapping **Regenerate** discards an unsaved edit with no confirm.
- **A genuine Anthropic I/O failure surfaces as a bare `500`** (`serveJson` has no try/catch) — the client surfaces it via the inline caption error; "never 500" in the plan covered *missing theme/thin context* (handled), not a real upstream outage.
- **Caption isn't auto-written at generation time** — it's generated lazily on first Reveal + on demand; wiring it into `generate`'s background job is a later option.
