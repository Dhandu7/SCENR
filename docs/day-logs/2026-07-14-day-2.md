## Assumptions / gaps (accepted, not fixed)

- **Storage RLS policy duplication** (`trip_media_owner_select` / `renders_owner_select` share near-identical logic) — flagged by both the simplification and altitude review angles as a real duplication risk (the exact bug class just fixed could recur if a third bucket is added and only one policy is updated). Judged as over-engineering to extract into a shared SQL function for two static buckets at this stage; skipped rather than adding risk to an already-fixed security policy. Revisit if a third bucket is ever added.
- **No thumbnailing/render pipeline** — thumbnails are signed URLs to the original uploaded file; video tiles show a placeholder + duration/play badge, not a real extracted frame. Explicit scope trim per the plan; real rendering is a later day.
- **`duration_seconds` still unpopulated** — nothing in the upload chain captures it yet; the badge renders conditionally and simply doesn't show for any item today. Unchanged from Day 1's accepted gap.
- **Signed URLs fetched per trip-load, not cached** — acceptable at MVP test-data scale; a real caching/CDN strategy is a later concern.
- **No "Generate ✦" CTA, no trips archive** — both explicit scope trims; the generate function and archive screen don't exist yet.
- **HEIC images still don't render in a web browser** (browser-native limitation, not a app bug) — visible in test data as blank tiles for HEIC uploads; will render correctly on a real iOS/Android device build, just not in the Expo-web preview used for verification.
- **Test data accumulating in the live database** — a new test trip/upload was added today (`Stampede 2026`, `live-verify.jpg`) on top of Day 1's test trips. Cosmetic only, same as Day 1's note; still worth a clean slate before any real demo.
