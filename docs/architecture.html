Reading the map

Five layers, top to bottom. Fast CRUD lives up top; async, GPU-heavy work lives in the Creation and Intelligence rows; shared state sits in Data/ML; third parties sit at the bottom.

Trip domain (row 1)

  • Stateless request/response + realtime.
  • Your always-on, cheap-to-scale tier.
  • Auth, Trip, Invite, Ingestion, Pool.

Creation domain (row 2)

  • Async, queue-driven, GPU-backed.
  • Orchestrator → Pipeline → Render.
  • Scales independently of the API.

Intelligence domain (row 3)

  • Model-serving, called by the pipeline.
  • Theme, Music, Caption, Insights.
  • Offline Research feeds Theme (async).

API Gateway / BFF — deep dive

Kong at the edge · Apollo Federation GraphQL BFF · thin REST for the appless path. Stateless, owns no domain data.

Responsibilities

  • Single entry point for the mobile app and the appless web uploader; hides service topology from clients.
  • Edge concerns: TLS termination, routing, request/response transforms, API versioning, WAF + bot protection (public join links).
  • AuthN/Z: validates JWTs against the Auth service JWKS; authorizes the WebSocket handshake.
  • Rate limiting + quota pre-checks — calls Quota & Billing before admitting startGeneration.
  • BFF aggregation: composes many subgraph calls into one client payload; response caching for read-heavy queries.
  • Upload brokering: hands back presigned URLs so media never flows through the gateway.
  • Observability: distributed tracing, metrics, structured access logs.

Explicitly NOT its job

  • No business logic, no domain persistence — that stays in each service.
  • No media bytes on the request path.

Tech stack

  • Kong Gateway (L7): routing, JWT/rate-limit/WAF plugins, canary, declarative config via decK.
  • Apollo Federation (Node/NestJS subgraphs): one GraphQL schema stitched across Trip, Media Pool, Generation, Insights.
  • Thin REST edge for appless: join, upload-session, contribute.
  • Redis: distributed rate-limit counters + response/APQ cache.
  • Realtime: GraphQL subscriptions / Cloudflare + Redis pub/sub for live pool & progress.
  • OpenTelemetry → tracing; Apollo Studio schema registry.

Key APIs & events

  • GraphQL queries: trip, mediaPool, generations, insights.
  • Mutations: createTrip, invite, requestUploadUrl, startGeneration, setCaption.
  • Subscriptions: mediaAdded, generationProgress, generationReady.
  • Appless REST: POST /join/:slug, POST /uploads.
  • Consumes generation.* from the Orchestrator (via Redis/Kafka) to push to clients.

Data ownership

  • Owns no domain data — fully stateless.
  • Ephemeral only: rate-limit counters, short-lived response cache, compiled GraphQL schema, JWKS keys.
  • Config as code (decK / schema registry); each service remains its own source of truth.

How it scales

  • Stateless horizontal replicas behind an LB; autoscale on RPS/CPU. Kong data-plane scales apart from control plane.
  • Shared limit state in Redis, so any replica enforces the same quota.
  • GraphQL: persisted queries (APQ), DataLoader batching to kill N+1, edge caching of cacheable reads.
  • Uploads bypass the gateway via presigned URLs — the #1 scale lever.
  • WebSockets fan out through Redis pub/sub (not sticky in-process sockets).
  • Resilience: circuit breakers, timeouts, bulkheads; shed load / serve cache on overload. Harder limits on public appless routes.
  • Global: CDN + regional gateway PoPs.
